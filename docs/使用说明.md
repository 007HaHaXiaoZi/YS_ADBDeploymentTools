# YS_ADBDeploymentTools v2.0.0

## 运行

在 Windows x64 电脑双击 `YS_ADBDeploymentTools.exe`，无需另装 .NET。ADB 从 `tools/adb.exe`、`tools/platform-tools/adb.exe`、`platform-tools/adb.exe` 或 Windows PATH 查找；需要提供完整且一致的 platform-tools，不能混用 DLL。

每次启动都会异步检查 GitHub 更新，同时检测 ADB 和设备。没有 ADB、没有设备或更新站点暂时不可达，都不会阻塞另一项操作。

## 准备本地资源

默认资源只在 EXE 旁的 `tools` 中查找：

```text
YS_ADBDeploymentTools.exe
tools/
  COMO_UN..._QC.apk
  COMO_UN..._DL.apk
  COMO_LA....apk
  libdsp_wrapper.so
  libXrSlamInterface.so
  YsSlamSensorSettingConfig.yaml
  CameraParametersSY.json
  CameraEffect.json
```

GitHub 仓库和更新附件不包含 tools；资源应通过你们已有的内部方式提供。历史目录中的不同内容资源保存在本地 `tools/archived-resources/`，不参与默认扫描。

每一行可点“选择…”指定其他路径，文件名不必与目标配置文件相同，但扩展名需要匹配。Unity APK 的名称仍须包含 `Unity` / `COMO_UN` 及对应大写 `QC` / `DL`，以防选错型号。“默认”清除这一行的自定义路径，重新扫描 tools。

QC 和 DL 的自定义 APK 选择分别记忆。其他组件路径、覆盖选项保存在本地 `deployment-options.json`，不会上传仓库或随程序更新覆盖。

## 设备状态

连接并授权 USB 调试后，点击“刷新设备与文件”，选择目标设备。多个设备连接时必须明确选择。

“设备状态”位于“是否覆盖 / 安装”前：

- **已安装 / 未安装**：根据 APK 的真实包名和设备的 `pm list packages` 结果判断，不使用 APK 文件名猜测。
- **已存在 / 不存在**：检测对应 Android 路径。
- **检测失败 / 包名未知**：设备离线、权限不足、包名无法解析或命令失败，不能当成未安装或不存在。

本项目默认包名：Unity 为 `com.horeal.UnityAndroid`，Launcher 为 `com.horeal.xrlauncher`。自定义 APK 会使用从其清单读取的包名；没有本地 APK 时仍能检测上述默认应用。QC/DL 共用 Unity 包名，“已安装”表示该包存在，不代表已验证设备上的 QC/DL 版本与本地一致。

检测先读取应用和文件状态。文件访问返回 Permission denied 时，每轮最多验证或获取一次 root 并重试；已有 uid=0 时跳过 adb root。仍被拒绝时显示“权限不足”，双击状态查看原因。检测不会执行 remount、重启设备、安装或替换；写入部署仍执行 root + remount。更换设备或本地文件会重新检测，过期的检测结果不会显示到新设备上。

YAML 的设备完整路径为 `/mnt/vendor/persist/calibdata/slam/YsSlamSensorSettingConfig.yaml`。悬停预览最多显示 8 行，每行最多 50 个字符；双击名称或设备状态打开可滚动内容窗口。

## JSON / YAML 预览

- 悬停“设备状态”：显示设备文件内容。
- 悬停“部署部分名称”或“本地文件”：显示当前选中本地文件内容。
- 双击部署部分名称：打开本地内容窗口。
- 双击设备状态：打开设备内容窗口。

预览最多读取 64 KiB。较长的悬停文字会提示截断，可双击打开可滚动窗口；设备文件存在但无读取权限时，会显示内容读取失败，仍保留“已存在”的状态。

## 覆盖部署

每行独立选择“覆盖”或“跳过”，点击“执行选中项目”后执行全部选中部分。已移除“仅 SLAM”“仅 Unity/相机配置”“仅 Launcher”的独立按钮及分组入口。

“全部覆盖”“仅 SO 和应用”“全部跳过”是快捷选择，仅改变每行设置，不立即执行。

| 部分 | Android 目标 |
|---|---|
| Unity / Launcher APK | `adb install -r`，保留应用数据，不自动卸载 |
| libdsp_wrapper.so | `/vendor/lib64/libdsp_wrapper.so` |
| libXrSlamInterface.so | `/vendor/lib64/libXrSlamInterface.so` |
| YsSlamSensorSettingConfig.yaml | `/mnt/vendor/persist/calibdata/slam/YsSlamSensorSettingConfig.yaml` |
| CameraParametersSY.json | `/sdcard/Android/data/com.horeal.UnityAndroid/files/CameraParametersSY.json` |
| CameraEffect.json | `/sdcard/Android/data/com.horeal.UnityAndroid/files/CameraEffect.json` |

覆盖任一 SLAM 库或 YAML 后，所有选中项目部署成功时执行 sync 并自动重启设备。覆盖 Launcher 仍会备份系统 Launcher3QuickStep；同时部署 SLAM 和 Launcher 时仅在末尾重启一次。只有 Unity APK / 相机 JSON 时不自动重启。任务中途失败不发送末尾重启命令。仅检测和导出不会调用这些修改操作。库和配置先上传同目录临时文件，验证大小后再替换；任务失败会停止后续操作，已完成的 Android 写入不会自动整体回滚。

## 清除 Unity 数据与同步时间（2.0.2）

选择目标设备后，点击红色“清除 Unity 数据”按钮并确认。工具读取当前 Android 用户，只对 `com.horeal.UnityAndroid` 执行 `pm clear`，保留 APK，清除设置、缓存及应用数据，相机配置需要重新部署。可先导出 Unity files 备份；导出不包含应用私有设置。命令退出成功且返回 `Success` 后才报告完成。[Android 官方 pm clear 说明](https://developer.android.com/tools/adb#pm)。

“同步设备时间”按钮先验证或获取 root，再将设备时钟同步到当前电脑时间，并回读 Unix 时间，误差超过 5 秒时报告失败。保持设备时区和自动时间设置；自动校时开启时，系统之后可能再次校准。电脑时间须正确。此功能不执行 remount 或重启。

更新提示、准备就绪、安装完成等执行状态为红色。上述按钮与部署、导出互斥，任务执行时禁止重复点击。

## 导出 Unity 文件夹

点击“导出 Unity files…”，选择任意本地目录。工具把 `/sdcard/Android/data/com.horeal.UnityAndroid/files/` 内全部内容，包括子目录，下载到选定目录中新建的 `UnityFiles-设备号-时间-唯一编号` 子目录。

每次导出使用独立目录，避免覆盖已有文件。导出失败会保留已下载的部分文件。它不会删除、修改设备文件，也不会自动申请 root；设备须允许读取该路径。

## 更新

默认地址及签名公钥已经内置：

`https://github.com/007HaHaXiaoZi/YS_ADBDeploymentTools/releases/latest/download/manifest.json`

这是 Git SSH 仓库地址对应的 HTTPS 下载入口，不需要在 PC 上配置 Git 或 SSH。每次启动检查一次；运行期间默认每 60 分钟检查，可在设置里调整周期。

发现新版后显示提示；点击“下载并更新客户端”才下载、校验签名与哈希、退出、替换 EXE 并重启。更新不会覆盖 tools、用户自定义路径或导出文件。执行部署/导出时不能开始替换 EXE。

旧的中文名称程序需要先人工更换为本版，之后使用统一文件名 `YS_ADBDeploymentTools.exe`。请勿自行重命名，否则更新器无法定位主程序。
