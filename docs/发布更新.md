# 发布 GitHub 更新

发布入口为根目录的 `YS_ADBReleaseTool.exe`，集成签名打包、Git 文件提交推送、GitHub 附件上传和 Release 发布。双击打开交互菜单，也可以在终端调用。不依赖 PowerShell 或 GitHub CLI；Git 操作和凭据读取需要安装 Git for Windows。

## 双击使用

1. **生成本地签名更新包**：输入仓库目录、版本和说明，只生成本地文件。
2. **推送已有提交并上传发布 Release**：检查版本、仓库及已提交状态，打包并推送当前分支，然后上传三个附件，全部核对成功后公开为 Latest。
3. **选择文件、提交并推送 Git**：输入提交说明和具体文件路径，多个路径用 `|` 分隔。例如 `src/AdbDeploymentTool/Updates.cs|src/AdbDeploymentTool/AdbDeploymentTool.csproj|src/AdbDeploymentTool/app.manifest|YS_ADBDeploymentTools.exe`。

菜单每次执行一项后等待回车关闭，再次双击可继续下一项。默认使用发布工具所在目录作为仓库根目录。生成目录默认为 `.build/releases/版本-时间-随机编号/`。

## 发布前准备

发布私钥放在本机 `.release-private/publisher-private.pem`，与客户端内置公钥配套。升级必须继续使用同一密钥；不要把私钥放到客户端目录或 GitHub。

本机先完成 HTTPS 登录：

```powershell
git credential-manager github login --url https://github.com --username 007HaHaXiaoZi
```

新版本必须高于已公开版本。例如发布 `2.0.2`：先同步修改客户端 `Updates.cs`、`AdbDeploymentTool.csproj`、`app.manifest` 的版本，然后构建：

```powershell
.\scripts\Build.ps1
```

有完整 NuGet 缓存时可加 `-Offline`。发布工具会检查已构建 EXE 的文件版本与本次版本一致；它不修改源码版本，也不执行编译。

## 全部通过 EXE 提交与发布

只提交明确指定的文件，不会自动添加整个工作目录。暂存区已有内容时停止，防止混入其他工作。

```powershell
.\YS_ADBReleaseTool.exe git-upload --message 'Release v2.0.2' --file src/AdbDeploymentTool/Updates.cs --file src/AdbDeploymentTool/AdbDeploymentTool.csproj --file src/AdbDeploymentTool/app.manifest --file YS_ADBDeploymentTools.exe
.\YS_ADBReleaseTool.exe release 2.0.2 --notes '更新说明' --upload --push
```

`git-upload` 提交后推送当前分支；推送失败时本地提交保留。发布命令的 `--push` 可重试推送已有提交，不会强制推送。发布前需处理所有已跟踪文件的未提交改动；未跟踪文件不会被自动上传。Release 固定关联此次核实的 Git 提交。

只生成本地包：

```powershell
.\YS_ADBReleaseTool.exe release 2.0.2 --notes '更新说明'
```

更多选项：

```powershell
.\YS_ADBReleaseTool.exe --help
.\YS_ADBReleaseTool.exe release 2.0.2 --root D:\YSKJ\como --notes '更新说明' --output D:\YSKJ\como\.build\releases\custom-new --upload
```

省略 `--push` 时，要求 GitHub 上的当前分支已与本地提交一致。`--output` 必须是新目录。可用 `--key` 指定私钥，`--repository owner/repo` 指定仓库；origin 推送地址必须与该仓库一致。

## 发布内容与失败处理

Release 包含且仅包含：

- `YS_ADBDeploymentTools.exe`
- `manifest.json`
- `manifest.json.sig`

tools 由用户在本地维护。私钥、本地资源和运行数据不会被打包。签名后的清单不要手工修改。工具通过 Git Credential Manager 在内存中读取凭据，不显示或保存令牌，携带令牌的请求不跟随重定向。

已有同名 Release（包括草稿）或标签会被拒绝覆盖。上传中断时保留草稿，程序显示 Release ID；到仓库 Releases 检查附件。确认要从头重试时手动删除该未完成草稿，再重新运行发布命令。若公开请求响应丢失，先检查 GitHub 是否已经发布，避免重复操作。

客户端检查地址：

```text
https://github.com/007HaHaXiaoZi/YS_ADBDeploymentTools/releases/latest/download/manifest.json
```

## 兼容旧命令

`keygen`、`publish`、`publish-github` 仍保留原有本地生成行为。旧的 `scripts/Publish-Release.ps1` 现在只是 EXE 的参数转发入口，`-Upload` 对应 `--upload`，新增 `-Push` 对应 `--push`。

## 验证

构建脚本包括客户端测试和发布工具测试。发布工具测试使用模拟 GitHub 接口，覆盖重复版本、版本倒退、分页草稿检查、附件哈希、上传中断与发布顺序，不访问真实 GitHub。

打包回归测试：

```powershell
.\tests\Test-GitHubPublisher.ps1
.\tests\Test-PackagedUpdater.ps1
```

发布后先在测试客户端验证下载、替换和重启，再分发。客户端当前版本与 Latest 一致时显示“已是最新版本”是正常行为。
