# 发布 GitHub 更新

仓库：`007HaHaXiaoZi/YS_ADBDeploymentTools`。客户端使用公开 Release 的 HTTPS 下载地址；Git SSH 地址仅用于开发者推送代码。

## 密钥

`publisher-public.pem` 是公开的发布者公钥，已嵌入客户端并提交仓库。

发布私钥保存在原发布电脑的 `.release-private/publisher-private.pem`，被 Git 忽略。请单独安全备份；不要上传 GitHub，不要放进 tools，也不要随客户端下载。后续版本继续使用同一私钥，否则旧客户端不会信任新签名。

## 构建和测试

安装 .NET 9 SDK，在项目根目录执行：

```powershell
.\scripts\Build.ps1
```

脚本构建、测试并输出根目录的 `YS_ADBDeploymentTools.exe` 和 `YS_ADBReleaseTool.exe`。若已有完整 NuGet 缓存，可加 `-Offline`；`-SkipTests` 只用于已经完成验证的重复打包。

## 生成并上传

先修改 `Updates.cs`、客户端 csproj 和 app.manifest 中的版本，使本次版本递增，例如 `2.0.1`，构建并提交源码和新 EXE。保持 tools、私钥和用户数据不进入提交。

本机需已完成 GitHub HTTPS 登录：

```powershell
git credential-manager github login --url https://github.com --username 007HaHaXiaoZi
```

生成本地签名附件：

```powershell
.\scripts\Publish-Release.ps1 -Version 2.0.1 -Notes '更新说明'
```

确认 GitHub 上代码已更新后，首次生成时可加 `-Upload` 直接创建草稿、上传全部附件并发布为 Latest：

```powershell
.\scripts\Publish-Release.ps1 -Version 2.0.1 -Notes '更新说明' -Upload
```

输出目录每次必须是新目录。若先生成了本地包，再决定用脚本上传，可传一个新的 `-OutputDirectory`；已经存在的 Release 不会被覆盖。

Release 包含且仅包含：

- `YS_ADBDeploymentTools.exe`
- `manifest.json`
- `manifest.json.sig`

**不包含 tools。** 签名清单里的文件 URL 固定到版本标签，客户端检测地址固定到 Latest；两个地址各自用途不同。签名后的清单不可手工编辑，所有文件上传完成前不要公开不完整版本。

`scripts/Publish-Release.ps1` 从本机 Git Credential Manager 读取 HTTPS 凭据到内存，调用 GitHub API，不将令牌写入文件或日志。它不要求额外安装 GitHub CLI。

## 验证

从另一台 PC 下载客户端，在没有 ADB 的情况下启动也应能检查更新。升级到更高版本时，先在一台测试 PC 验证下载、替换及重启，再通知其他使用者。

首次发布与当前客户端版本相同，客户端显示“已是最新版本”是正常行为；后续发布更高版本才显示更新。
